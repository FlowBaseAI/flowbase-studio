# Astro 开发规范

## 架构原则

- 默认使用 `.astro` 组件——它们不输出 JS
- 只有在需要交互时才使用框架组件（React、Preact、Svelte）
- 谨慎使用 `client:load`——优先 `client:visible` 或 `client:idle`
- Island 组件尽量小且自包含
- 数据获取在 `.astro` frontmatter 中完成，不在客户端组件中

## Content Collections

- 始终用 `z` 定义 Schema 进行 frontmatter 类型验证
- 使用 `getCollection()` 进行类型安全的数据访问
- 内容存放在 `/src/content/`——禁止放在 `/public/`
- 需要组件的内容用 MDX，纯文本用 `.md`

## 性能规范

- 所有图片通过 `astro:assets` 的 `<Image>` 组件优化
- 字体通过 `preconnect` 和 `font-display: swap` 处理
- 不要有未使用的 JavaScript——用 Network 标签验证
- 非必要 SSR 时优先使用静态生成（`output: 'static'`）

## 组件模式

- 在 frontmatter 中用 TypeScript interface 定义 Props
- 为可选 Slot 提供默认内容
- 使用 `Astro.props`——不要在 script 标签中解构 props
- 用 `define:vars` 将服务端数据传给内联脚本

## 路由规范

- 页面文件保持精简
- 动态路由静态生成使用 `getStaticPaths()`
- API 路由放在 `/src/pages/api/`，处理正确的 HTTP 方法

## 样式规范

- `.astro` 组件默认使用 Scoped Styles
- 全局样式只用于 reset、CSS 变量和排版
- 优先使用 Tailwind 工具类而非组件级 CSS
