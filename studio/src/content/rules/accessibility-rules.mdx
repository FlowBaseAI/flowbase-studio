# 无障碍开发规范

## 语义化 HTML

- 使用合适的 HTML 元素——`<button>` 而非 `<div onClick>`
- 标题层级：H1 → H2 → H3，禁止跳级
- 使用地标元素：`<main>`、`<nav>`、`<aside>`、`<footer>`
- 列表使用 `<ul>`/`<ol>`，而非重复的 `<div>`
- 每个输入框必须有关联的 `<label>`

## 键盘导航

- 所有交互元素必须键盘可访问
- 所有可聚焦元素有可见的焦点指示器
- Tab 顺序符合视觉阅读顺序
- Esc 键关闭弹窗和下拉菜单
- 禁止键盘陷阱（用户可以随时 Tab 离开）

## ARIA 规范

- 只在语义 HTML 解决不了时才使用 ARIA
- 无可见文字的元素使用 `aria-label`
- 补充说明使用 `aria-describedby`
- 弹窗使用 `role="dialog"` 和 `aria-modal="true"`
- 动态内容更新使用 `aria-live`
- 可展开内容使用 `aria-expanded`

## 图片与媒体

- 有意义的图片提供描述性 `alt` 文字
- 装饰性图片使用 `alt=""`（空字符串）
- 所有视频内容提供字幕
- 仅有视觉信息的视频提供音频描述

## 颜色与对比度

- 文字对比度：最低 4.5:1（大字体 3:1）
- 禁止只用颜色传递信息
- 灰度测试（去掉颜色后功能还能理解吗？）

## 表单规范

- 明确标识必填字段（视觉 + 程序化）
- 错误信息要指出是哪个字段、问题是什么
- 相关字段用 `<fieldset>` 和 `<legend>` 分组
- 个人信息字段使用 autocomplete 属性
