# API 开发规范

## URL 设计

- 集合使用复数名词：`/users`、`/posts`
- 归属资源使用嵌套路由：`/users/{id}/posts`
- 小写 + 连字符：`/blog-posts`
- URL 中禁止出现动词——用 HTTP 方法表达动作
- URL 包含版本号：`/v1/`、`/v2/`

## HTTP 方法与状态码

| 操作 | 方法 | 成功状态码 |
|------|------|-----------|
| 读取集合 | GET | 200 |
| 读取单条 | GET | 200 |
| 创建 | POST | 201 |
| 替换 | PUT | 200 |
| 更新 | PATCH | 200 |
| 删除 | DELETE | 204 |

错误码：400（请求错误）、401（未认证）、403（无权限）、404（不存在）、409（冲突）、422（数据验证失败）、429（限流）、500（服务器错误）

## 响应格式

```json
{
  "data": { ... },
  "meta": { "total": 100, "page": 1, "per_page": 20 },
  "errors": []
}
```

## 错误格式

```json
{
  "errors": [{
    "code": "VALIDATION_ERROR",
    "message": "邮箱格式不正确",
    "field": "email"
  }]
}
```

## 文档规范

- 所有端点必须有 OpenAPI 3.0 文档
- 所有端点提供请求/响应示例
- 记录所有错误码及其含义
- 清晰说明认证方式

## 速率限制

- 响应头包含 `X-RateLimit-Limit`、`X-RateLimit-Remaining`、`X-RateLimit-Reset`
- 超限时返回 429
- 认证端点设置更严格的限制
