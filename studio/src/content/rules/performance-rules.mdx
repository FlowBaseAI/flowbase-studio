# Web 性能规范

## Core Web Vitals 目标

- **LCP**（最大内容绘制）：`<2.5秒`
- **INP**（交互响应时间）：`<200ms`
- **CLS**（累积布局偏移）：`<0.1`

## 加载性能

- 预加载 LCP 资源（Hero 图片或字体）
- 折叠线以下图片使用 `loading="lazy"`
- LCP 图片使用 `fetchpriority="high"`
- 内联关键 CSS（首屏样式）
- 非关键 JavaScript 延迟加载（defer/lazy）
- 对第三方源使用 preconnect

## 图片规范

- 使用现代格式：WebP 或 AVIF
- 指定 `width` 和 `height` 防止 CLS
- 使用 `srcset` 提供响应式图片
- 图片压缩目标：Hero 图 WebP `<100KB`，缩略图 `<30KB`

## JavaScript 规范

- 每个路由 Bundle 大小预算：gzip 后 `<150KB`
- 路由级别代码分割——不要单一巨型 Bundle
- Tree shaking 去除未使用的导出
- 避免为一个函数引入整个库

## 字体规范

- 正文字体优先使用系统字体栈
- 自定义字体子集化（只包含实际使用的字符）
- 使用 `font-display: swap` 防止 FOIT
- 折叠线以上使用的字体做 preload

## 性能监控

- 每个 PR 的 CI 流程中跑 Lighthouse
- 在慢速 3G 网络下测试，而非只在 WiFi 下
- 生产环境部署真实用户监控（RUM）
- 性能回退时触发预算告警

## 运行时性能

- 避免强制布局（读取后再写入 DOM，禁止交替读写）
- 动画使用 `requestAnimationFrame`
- scroll/resize 事件处理函数做防抖
- 超过 100 条记录的列表使用虚拟滚动
