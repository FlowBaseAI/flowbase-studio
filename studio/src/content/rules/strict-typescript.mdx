# Strict TypeScript Rules

## tsconfig.json Requirements

```json
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noImplicitReturns": true,
    "noFallthroughCasesInSwitch": true,
    "forceConsistentCasingInFileNames": true
  }
}
```

## Zero Escape Hatches

- `any` is banned — use `unknown` + type narrowing
- `as` casts require comment with justification
- `!` non-null assertions require comment with proof
- `@ts-ignore` is forbidden
- `// eslint-disable` requires ticket number in comment

## Exhaustive Pattern Matching

```typescript
// Always handle all union cases
function assertNever(x: never): never {
  throw new Error(`Unhandled case: ${x}`)
}

switch (action.type) {
  case 'ADD': return handleAdd(action)
  case 'REMOVE': return handleRemove(action)
  default: return assertNever(action.type) // compile error if case missing
}
```

## Result Types (No throw)

```typescript
type Result<T, E = Error> =
  | { success: true; data: T }
  | { success: false; error: E }
```

Use Result types for operations that can fail. Reserve `throw` for truly exceptional, unrecoverable errors.

## Generic Constraints

- All generics must have meaningful constraints
- Document what T is in JSDoc when non-obvious
- Avoid unconstrained `T` when you know the shape
