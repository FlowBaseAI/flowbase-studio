# 通用开发规范

## 代码质量

- 代码正确性第一，可读性第二，性能第三
- 明确优于隐式
- 不要添加超出需求的功能、抽象或错误处理
- 三行相似代码比过早抽象更好
- 禁止提交未完成的实现

## 沟通规范

- 直接、简洁——不要不必要的开场白
- 做事前先说明要做什么
- 遇到阻碍立即报告，不要悄悄绕过
- 不确定时提出针对性问题，而不是猜测

## 决策原则

- 优先选择解决问题的最简方案
- 在不同方案中明确说明权衡取舍
- 默认遵循代码库中的现有规范
- 引入新依赖需要明确理由

## 注释原则

- 默认不加注释
- 只对非显而易见的「为什么」加注释，不注释显而易见的「是什么」
- 禁止描述代码已经清楚表达的内容的注释

## 安全原则

- 禁止硬编码密钥或凭证
- 在系统边界验证所有用户输入
- SQL 使用参数化查询，禁止字符串拼接
- 禁止在日志中记录敏感数据（密码、Token、个人信息）
