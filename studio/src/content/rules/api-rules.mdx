# API Development Rules

## URL Design

- Plural nouns for collections: `/users`, `/posts`
- Nested for owned resources: `/users/{id}/posts`
- Lowercase, hyphen-separated: `/blog-posts`
- No verbs in URLs — use HTTP methods
- Version in URL: `/v1/`, `/v2/`

## HTTP Methods & Status Codes

| Action | Method | Success Code |
|--------|--------|--------------|
| Read collection | GET | 200 |
| Read single | GET | 200 |
| Create | POST | 201 |
| Replace | PUT | 200 |
| Update | PATCH | 200 |
| Delete | DELETE | 204 |

Error codes: 400 (bad request), 401 (unauthenticated), 403 (forbidden), 404 (not found), 409 (conflict), 422 (validation), 429 (rate limited), 500 (server error)

## Response Format

```json
{
  "data": { ... },
  "meta": { "total": 100, "page": 1, "per_page": 20 },
  "errors": []
}
```

## Error Format

```json
{
  "errors": [{
    "code": "VALIDATION_ERROR",
    "message": "Email is invalid",
    "field": "email"
  }]
}
```

## Documentation

- Every endpoint documented in OpenAPI 3.0
- Request/response examples for all endpoints
- Error codes and their meanings documented
- Authentication method clearly documented

## Rate Limiting

- Include `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` headers
- Return 429 when limit exceeded
- Stricter limits on auth endpoints
