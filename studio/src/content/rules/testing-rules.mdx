# 测试规范

## 测试金字塔

- **单元测试**（70%）：快速、隔离、只测一件事
- **集成测试**（20%）：测试组件间的交互
- **E2E 测试**（10%）：只测关键用户路径

## 什么值得测

必须测试：
- 正常路径（常规使用场景）
- 边界情况（空值、null、零、最大值）
- 错误路径（无效输入、失败场景）
- 安全边界（认证、授权）

不需要测试：
- 第三方库的内部实现
- 实现细节（重构时会变的东西）
- 显而易见正确的简单代码（Getter/Setter）

## 测试质量要求

- 每个测试只有一个断言焦点
- 测试名称描述行为：`it('当用户不存在时应该返回 404')`
- 测试之间相互独立，无共享可变状态
- 可确定性——每次运行结果相同
- 快速——单元测试每个不超过 50ms

## 测试结构（AAA 模式）

```
// Arrange（准备）
const user = buildUser({ role: 'admin' })

// Act（执行）
const result = canAccessDashboard(user)

// Assert（断言）
expect(result).toBe(true)
```

## 覆盖率要求

- 业务逻辑：80% 以上行覆盖率
- 安全关键代码：100%
- 覆盖率是指标，不是目标——不要为了数字写无意义的测试

## 测试数据规范

- 使用工厂函数，而非硬编码对象
- 可以的话用随机数据（使用 faker 生成真实数据）
- 用真实数量级的数据测试（不要只测 1 条记录）
- 每个测试结束后清理测试数据
