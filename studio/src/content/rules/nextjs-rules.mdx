# Next.js App Router 规范

## Server vs Client 组件

- 默认使用 Server Components——更快，零 Bundle 成本
- 只有在需要浏览器 API、事件处理、状态或副作用时才加 `'use client'`
- `'use client'` 边界尽量靠近组件树底部
- 禁止在 Client 组件中导入 Server 组件

## 数据获取

- 在 Server 组件中直接 `async/await` 获取数据
- 用 `cache()` 在请求间去重 fetch 调用
- ISR 使用 `revalidate`：`export const revalidate = 60`
- 数据库查询缓存使用 `unstable_cache`

## 路由规范

- `page.tsx` 用于路由，`layout.tsx` 用于共享 UI
- `loading.tsx` 提供即时加载 UI（React Suspense）
- `error.tsx` 用于错误边界
- 路由分组 `(group)` 用于组织，不影响 URL
- 平行路由 `@slot` 用于复杂布局

## 性能规范

- 所有图片使用 `next/image`——禁止 `<img>`
- 所有字体使用 `next/font`——禁止外部 `<link>`
- 所有内部导航使用 `next/link`
- 重型客户端组件使用动态导入

## Server Actions

- Server Actions 中必须进行服务端输入验证
- 数据变更后使用 `revalidatePath` 或 `revalidateTag`
- 处理错误并返回类型化的响应

## 环境变量

- 公开变量使用 `NEXT_PUBLIC_` 前缀
- 服务端专用变量禁止暴露给客户端
- 使用带 Zod 验证的 `env.ts` 实现类型安全的环境变量
