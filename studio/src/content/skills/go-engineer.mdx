## Go 惯用法

### 错误处理
```go
// Go 风格：显式返回错误
func readFile(path string) ([]byte, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return nil, fmt.Errorf("readFile %s: %w", path, err)
    }
    return data, nil
}

// 调用侧
data, err := readFile("config.json")
if err != nil {
    log.Fatal(err)
}
```

### 接口设计
```go
// 接口在使用方定义，而非提供方
// 接口要小（通常 1-3 个方法）
type Reader interface {
    Read(p []byte) (n int, err error)
}
```

### 并发
```go
// Goroutine + Channel
ch := make(chan Result)
go func() {
    ch <- compute()
}()
result := <-ch

// sync.WaitGroup
var wg sync.WaitGroup
for _, item := range items {
    wg.Add(1)
    go func(item Item) {
        defer wg.Done()
        process(item)
    }(item)
}
wg.Wait()
```

## Go 编码规范

- 错误变量命名：`err`，哨兵错误用 `Err` 前缀
- 包名小写，简洁，无下划线
- 接口名通常以 `-er` 结尾（Reader、Writer、Stringer）
- `context.Context` 总是第一个参数
- 避免 `init()`，优先用构造函数

## 常见性能优化

- 预分配 Slice：`make([]T, 0, n)`
- 字符串拼接用 `strings.Builder`
- 避免在循环中分配内存
- Profile before optimize：`go tool pprof`

## 项目结构

```
cmd/         # 程序入口
internal/    # 内部包（外部不可导入）
pkg/         # 可被外部导入的包
api/         # API 定义（Protobuf、OpenAPI）
```
